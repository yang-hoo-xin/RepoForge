# 用任务权限表达编辑范围与文件操作

> 文档归集：2026-11-04。来源 `codex/developer-preview-b` 提交 `3c17e14d5f7f22bd83cda27ed777ddbc010c115c`；原设计来源为 `codex/task-permission-design` 提交 `a19e52d4c99f8d37e0dfe17793dd4ce68b5f509e`。这是已接受的设计记录；本次归集不实施新文件权限或变更历史运行。

Status: accepted — Q1–Q9 已于 2026-11-01 获用户确认；仅设计决定已接受，尚未实施、回归或授予真实任务新权限。

适用范围：后续仓库 Task Agent v2 任务的编辑权限合同。设计基线为
`9619ea1ee2f138379ef17dfe4798ecd8b6fa91a3`；这份文档不改变现有运行的权限，也不属于
`codex/architecture-deepening` 上已验证的保持行为重构。
为什么要有它：权限语义变化需要独立设计与验证，不能借文档更新或结构重构扩张既有执行授权。

当前任务权限仅表达已有文件上的 `modify_existing`。新文件既不能提供已有文件前像，
也会改变候选、编译来源和验收所使用的文件集合；单独扩大路径清单不能完成新建文件支持。
这说明合同需要表达更多合法操作，并不证明某个具体任务必须通过新建文件解决。

## 已确认的决定

- **Q1：目录范围与操作分别授权。** 用户可以一次授予指定目录范围内的指定编辑操作；
  模型在该范围内自行选择文件及修改位置，无需逐文件重新批准。精确文件清单仍可用于更窄的任务范围。
  为什么要有它：任务权限规定允许做什么，技术方案由模型在权限内选择；文件清单不应成为唯一表达方式。
- **Q2：首批完整支持修改与新建。** 本次设计覆盖已有文件修改和新文件创建，并要求候选、检查、恢复及正式交付共同支持；
  删除文件和重命名留作后续明确决定，不从这次选择中推导出支持或授权。
  为什么要有它：先闭合已经暴露的操作缺口，避免把更多操作的历史和恢复语义默认为已经解决。
- **Q3：提供显式的权限调整申请。** 模型可说明需要调整的路径、操作和理由；
  宿主先判断是否能复用有效的既有授权，确实新增权限时交给用户决定。申请本身不授权，也不计作普通参数纠错。
  为什么要有它：权限缺口需要明确处理路径，反复修改参数不能产生新的合法权限。
- **Q4：区分普通开发测试与冻结验收输入。** 普通开发测试可以进入明确授权的修改或新建范围；
  登记为冻结验收的输入保持只读，两类内容按用途区分，不直接放开整个测试目录。
  为什么要有它：模型需要补充回归测试，但不能通过修改裁判使自己的补丁通过。
- **Q5：由宿主核验新文件不存在。** 新建操作在接纳候选和实际应用时，由宿主核验目标路径在相应当前版本中不存在，
  不要求模型提供空前像或读取不存在的文件；已有文件修改继续使用源码读取和精确前像检查。
  为什么要有它：新建和修改具有不同前提，创建操作不能意外覆盖已有文件。
- **Q6：权限扩大后用新运行身份承接任务。** 新增任务权限获批后，以新的任务运行身份承接同一业务任务，
  保留候选、历史和累计消耗，旧运行的权限和已形成的结果保持不变。
  为什么要有它：继续完成任务的同时，需要准确记录每段执行使用的权限及额外协助，不能事后改写原尝试。
- **Q7：申请需要人工决定时明确挂起。** 保存现场，停止 Task Agent 新增模型请求和工具动作；
  拒绝申请后，原权限和执行窗口仍有效时可以在原范围内继续；批准扩权后按 Q6 开启关联的新运行。
  权限等待有独立原因，不冒充工具执行结果未知。
  为什么要有它：避免等待期间空转和审批对象变化，也不把一次权限拒绝直接当成业务失败。
- **Q8：一次说明全部实际变更。** 审批同时展示权限变化、已有候选、累计消耗和剩余执行条件；
  复用仍有效的授权，需要新增时间、费用或披露范围时在同一次申请中明确提出。
  批准编辑范围不自动重置预算或延长期限。
  为什么要有它：既避免隐形续费和资源重置，也避免批准一次后接连追问已知的必要条件。
- **Q9：首批限定为 UTF-8 C# 源码及获准开发测试。** 构建配置、依赖声明和二进制文件不随目录授权自动开放；
  新文件必须确实进入适用编译，现有项目配置不能包含它时明确反馈，不私自修改项目文件。
  为什么要有它：在当前能力基础上完整交付新建操作，同时保留构建配置及依赖输入的独立合同。

## 与既有决定的关系

下述 ADR-0001、ADR-0002、ADR-0004 是来源分支中的既有决策编号；本归集分支尚未收录其全文，因此保留编号及原有关系，不提供未经核实可访问的远端链接。需要执行相关恢复或评测迁移时，应按本篇来源提交读取这些原件。


任务权限继续从宿主绑定配置派生；普通调用者、工具 schema 和模型输出都不是新的授权来源。
保留 ADR-0002 的正常入口所有权，不因加入申请动作开放任意 Authority 注入。
为什么要有它：表达更完整的任务权限，不等于把授予权限的权力交给任务模型或普通调用者。

权限政策变化形成新的评测版本，历史请求保留原解释，遵循 ADR-0001 与 ADR-0004。
Q6 的新运行承接不属于 ADR-0002 中权限不变的自动恢复；Q7 的拒绝后继续仍受原恢复核验及原截止时间约束。
复用既有批准只省去重复询问；若它实际扩张当前运行的任务权限，仍按 Q6 形成新运行。
为什么要有它：继续同一业务任务和继续同一次不可变任务运行是不同事实，旧运行不能事后获得新权限。

## 设计推导的执行与验证要求

以下要求落实 Q1–Q9 与现有合同，不增加新的操作、审批阶段或实现范围。
为什么要有它：设计需要能转成可观察的验收，不能停留在允许新文件的表面声明。

- 新建与修改使用各自明确的操作前提；未支持的操作、权限不足、参数错误和版本／路径冲突分别反馈。
  冻结验收输入不因可写目录覆盖而变得可写，工具能力不足也不能靠用户批准冒充已经支持。
  为什么要有它：模型需要知道应修正输入、选择其他合法方案还是申请权限，且获准不等于实现能力已经存在。
- 正常入口应完整证明：授权内修改与新建候选能够进入真实编译来源、公共检查、中断恢复和同版本源码及产物交付。
  普通开发测试可以补充反馈，不能替换冻结验收条件或由模型自己宣告独立验收通过。
  为什么要有它：路径放行不代表文件实际参与构建，也不代表任务已经完成。
- 新运行承接时重验权限、候选及当前源码；保留前驱运行、权限决定和资源来源，不把承接的历史重复计量。
  同一决定的重复处理不能产生额外运行或重复效果；未知效果先按既有对账要求处理。
  为什么要有它：批准回调、重试或恢复不能形成重复支出，旧候选也不能绕过当前版本检查。
- 挂起期间不以模型轮询等待用户；到达有效硬截止后沿用已有终态规则并保留等待权限的原因。
  批准扩权离开旧运行时，旧运行按实际未完成范围形成唯一结果；已形成的结果不改写。
  拒绝后已过期的运行不能复活，后续执行需要有效的新运行条件。
  为什么要有它：挂起、业务完成、权限受阻和超时必须准确区分，等待与批准都不能隐含延长原尝试。
- 验证同时覆盖正常路径及反例：目标已存在、接纳后被外部创建、越出授权范围、冻结验收写入、
  编译未包含新文件、拒绝后恢复、过期决定、重复决定和跨运行资源累计。
  为什么要有它：权限及恢复合同需要由可重复的行为证明，不能只检查 schema 接受输入。

## 实施范围与返回点

现有挂起只覆盖已有工具回执的特定交接中断，因此权限等待需要明确的挂起原因及决定回执，
通过既有正常任务运行入口衔接，不能直接伪装成旧的工具中断。
项目配置和依赖输入仍为冻结项；新增文件是否进入构建以实际编译输入为准。
为什么要有它：复用现有入口不等于省略新行为的合同，明确差异才能避免把未实施能力写成已有能力。

设计访谈至此收口。后续实施需要把本决定落实到完整纵向工单及针对性验证；真实模型回归另按实际配置与资源授权登记。
本次只修改文档，不自动启动模型任务、修改旧运行或合入任一分支；已验证的架构重构仍待用户决定合入。
为什么要有它：授权设计可以插队，但不能把已经完成的重构和原回归任务长期留在准备链中。
