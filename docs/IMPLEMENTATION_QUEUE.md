当前采用[真实交付与评测共同推进](EVALUATION_FIRST_CYCLE.md)：每次正常交付同时记录成败、成本和边界；具体短板触发针对性验证，候选采用再用独立任务检验。七项待测及其业务意义保留在[成果清单](PROJECT_OUTCOMES.md)。为什么要有它：交付产生真实样本，评测决定怎样改进，两者不互相等待“全部准备好”。

Transfer的td6/td7已结束，均未交付；诊断组增加调用和Token，仍重复失败代码，默认开关保持关闭。本轮结果已足以拒绝直接默认化；只在新证据或新假设可区分原因时重新进入开发，不把Transfer必过设为其他任务的前置条件。为什么要有它：结束一个负收益实验也是明确决定，不能让同题无限重试取代任务覆盖。

## 3. 执行方式

- 按当前失败定位必要源码、依赖和直接调用者，选择复用、适配或合同重设计；可以一起修改相关问题。为什么要有它：交付需要完整解决实际问题，旧实现和单因素实验方法不能替代工程判断。
- 完成选定行为及保留行为验收，记录真实入口、源码版本和适用副作用；复用已有原始回执，摘要只链接。为什么要有它：辅助函数通过、编译成功与任务完成有不同含义，重复报告不会增加证据。
- 并行调查和聚焦审阅，明确共享文件范围，完成后及时集成实跑。为什么要有它：审阅应消除具体风险并帮助交付，而不是不断产生新的前置阶段。

目标工程 Apply 消费精确绑定的人审或任务委托授权，保留真实来源；源码前像、目录范围、实际验收和外发/部署范围仍需一致。为什么要有它：取消重复人审等待不等于允许模型自授权或扩大修改。
