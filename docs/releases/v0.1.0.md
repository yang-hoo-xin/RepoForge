# RepoForge v0.1.0 Release Notes

Status: release candidate in progress. Do not create the tag or GitHub Release
until every item in the release gate below is verified against one exact commit.

为什么要有它：发布说明必须先区分当前能力、待验证检查和版本外工作，不能把工作区进度提前写成已发布事实。

## Positioning

RepoForge v0.1.0 is an evaluation and execution platform for local and
heterogeneous coding models, grounding delivery in repository evidence and real
tests.

中文定位：面向本地和异构模型、以源码证据和真实测试约束交付的 Coding Agent
评测与执行平台。

## Included scope

- Natural-language task routing into current-source investigation, planning,
  candidate generation, verification, review, and controlled delivery.
- Artifact and execution identities that bind a candidate to source inputs,
  test evidence, authorization, and resulting outputs.
- Local Ollama execution and configurable external-provider adapters.
- Deterministic evaluation and normal-entry checks that distinguish successful,
  failed, blocked, and unknown outcomes.
- An asynchronous HTTP/worker service layer and MCP interface that reuse shared
  product modules.
- Explicit repository profiles for currently supported SDK-style C# projects;
  domain-specific adapters remain examples rather than the product identity.

为什么要有它：首版范围需要说明用户实际获得什么，同时避免从已验证案例推导出任意仓库或任意模型都能成功。

## Result classification

Release documentation and evidence use these separate categories:

| Category | Meaning |
| --- | --- |
| Autonomous model result | A recorded model performed the investigated actions and produced the evaluated candidate. |
| Developer-assisted result | A developer or coding assistant supplied material implementation judgment or code. |
| Deterministic fixture | A scripted model, compiler, or evaluator verified platform control flow rather than model capability. |
| Environment qualification | Dependencies, source identity, build, or original tests were checked without claiming task repair. |
| Not completed | A required result remains failed, blocked, unknown, or not executed. |

为什么要有它：相同的测试通过可能证明平台接线、环境或模型修复中的不同一层，发布材料不能把它们合并成一种成功。

## Known limitations

- The release does not claim a measured general autonomous-repair success rate.
- Repository execution currently requires explicit profiles and declared test
  contracts; arbitrary repository autoconfiguration is not supported.
- Local execution copies work into controlled directories but is not an
  operating-system security sandbox for hostile code.
- Model-provider availability, latency, context limits, and credentials remain
  deployment-specific.
- Live Docker restart/replay, multi-client game runtime, long-duration service
  stability, and the external Serilog model task are not v0.1 guarantees.
- Research paths such as Self-RAG, LoRA, SFT, DPO, and cross-task memory are not
  default product behavior in this release.

为什么要有它：已知限制应在用户投入安装和运行成本前可见，也防止首版定位被误读为生产级或通用自主 Agent。

为什么要有它：每个复选项对应一个可检查的发布事实；未完成项保持可见，不能由计划、旧CI或不同修订上的测试替代。

The normal-entry demonstration command is:

```powershell
uv run --frozen python -m scripts.run_v0_1_demo --output artifacts/v0_1_demo --require-clean
```

It requires a .NET 8 SDK on `PATH`, or an explicit `REPOFORGE_DOTNET` path.
On Windows, `--workspace-parent <existing-short-path-directory>` can keep .NET
and artifact paths below legacy path-length limits.

Development verification has exercised both the workflow and continuous task
executors with real .NET 8 builds and behavior tests. That run used a dirty
working tree and therefore does not satisfy the unchecked candidate-commit gate
above; its purpose is to prove that the release demonstration itself is
executable before revision-bound verification.

## Deferred work and return point

Autonomous C5 repair, the Serilog A/A*/B comparison, live Docker restart and
rollback, game-specific runtime gaps, and training research remain in the
historical queue. They are reconsidered after v0.1.0 is released unless one of
them directly blocks the normal entry, release snapshot, or evidence accuracy.

为什么要有它：延后不等于删除；明确恢复点能保持长期要求，同时避免它们重新变成首版的无限前置链。
