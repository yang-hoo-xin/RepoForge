## What to build

让用户通过正常任务入口一次授予指定目录范围内的修改与新建权限，Task Agent 随后自行选择具体 UTF-8 C# 源码和获准普通开发测试，提交包含新文件的候选，经过公共检查、中断恢复和同版本源码及产物交付。已有文件清单仍可用于更窄的任务范围。

当前合同只支持已有文件修改，且候选、构建输入和验收来源均假定文件集合固定。本片同时贯通这些使用方，不以 schema 接受新建请求作为完成。
为什么要有它：用户要取得包含新文件的可验证交付，单独放开路径或工具参数仍会在后续检查和交付阶段阻断。

## Acceptance criteria

- [ ] 正常入口从宿主绑定配置派生目录范围和允许操作；有效授权内选择文件无需逐文件重新批准，精确文件清单仍可限定更窄范围。模型陈述、工具 schema、普通调用者提供的引用均不能自行授予权限。
  为什么要有它：用户控制权限范围，模型选择范围内的编辑方案，且权限来源保持可信。
- [ ] 新建与修改具有明确且不同的操作前提。新建在候选接纳与实际应用时核验当前目标不存在；已有文件修改保留源码读取和精确前像核验。新建文件可被正常读取、继续修改并参与后续候选修订，混合文件候选保留现有一致性要求。
  为什么要有它：新文件没有旧内容，不能伪造前像，也不能成为无法继续编辑的特殊产物或意外覆盖已有文件。
- [ ] 普通开发测试按用途进入明确授权范围，冻结验收输入始终保持只读。新增源码与开发测试纳入候选文件集合、构建来源及适用检查，记录能证明实际编译包含新文件；未包含时给出明确反馈，不悄悄改动项目配置、依赖或验收条件。
  为什么要有它：文件存在不等于参与构建，新增测试也不能替代冻结的业务判定。
- [ ] 一条正常入口场景完成已有文件修改、新建源码或获准开发测试、公共反馈、修订、中断恢复以及同版本交付。恢复保留同一任务运行身份、候选、观察和累计资源；交付包含实际新文件及对应产物，继续核验精确差异、当前源码和真实有效的 Apply／Build 授权。
  为什么要有它：完整链路才能证明用户能使用新建能力，编辑许可不能隐含额外执行副作用或丢失恢复历史。
- [ ] 反例覆盖目标已存在、接纳后被外部创建、越出授权范围、过期版本、冻结验收写入和新文件未参与编译；区分参数错误、权限不足、尚未支持的操作及版本／路径冲突。旧保存请求保持原解释，不回写旧运行。
  为什么要有它：拒绝必须指向真实原因，同时保持历史解释和已有安全约束。
- [ ] 通过正常任务入口和任务交付接口验证外部行为，使用受控模型响应与真实临时仓库，并保留实际编译输入的验证证据。保留首次失败、修复和聚焦复验；权限、效果及结果真实性经独立审阅，受控通过不宣称真实模型能力提升。
  为什么要有它：实施需要可重复的行为证据，不能用内部对象存在或测试替身自报成功替代验收。

## Blocked by

None。可以从已确认设计与现有正常入口开始；本片不依赖第二张权限申请工单。
为什么要有它：初始任务权限已经覆盖所需编辑时，不需要等待动态申请机制才能交付。

## Scope and return point

首批支持 UTF-8 C# 源码和获准普通开发测试的修改、新建。删除、重命名、构建配置、依赖声明及二进制文件不在本片内；权限申请与决定后的续接由第二张工单交付。
为什么要有它：本片闭合一个可独立验收的用户流程，其他操作不从目录授权中被默认为已经实现或获准。

使用独立实现分支并固定实际执行版本；验证后由用户决定合入。真实模型任务按实际模型、资源和披露条件另行登记；不启动、恢复或改写既有真实尝试。
为什么要有它：产品源码开发与真实任务执行各自需要明确版本及授权，不能借工单隐含启动付费或历史运行。

本片完成后返回第二张工单，并重新检查原回归与架构分支的队列；不把未合入的架构重构、正式批次、经验资格或换模型作为默认前置。
为什么要有它：只让直接技术依赖阻挡交付，避免权限改进演变为新的准备链。

## Related work

另一页的正常入口回归负责 Qwen 接线、LF／CRLF 输入解释、交付源码核验等直接阻断修复。2026-11-01 本次核对时，交付快照排序修复已形成 `29f66fe`，原始坏回复留存与安全格式纠错仍在开发。本片消费这些能力，只补目录权限、新建文件及其后续使用方，不重新实现通用模型接线、格式纠错或同题验收准备。
为什么要有它：这些修复与本片会经过共同执行模块，重复开发会产生两套处理方式并增加集成冲突。

设计提交仅固定已确认语义，不能被当作最新实现基线。实施前核对相关修复的稳定提交，集成时保留其行为并验证组合路径，不以旧文件覆盖另一页的新修复。需要对接的是直接相关补丁的稳定版本，不要求等待另一页整个业务回归成功。
为什么要有它：避免在旧版本上重复定位已修问题，同时不把另一条任务的最终成功设为新的全局前置。

- [#3：竞争性自主交付与策略经验评测](https://github.com/yang-hoo-xin/RepoForge/issues/3)：本片是产品能力开发，权限政策改变形成新评测版本，不改变该工单已经冻结的批次合同。

这些关联不是阻塞依赖，也不修改或关闭上述工单。
为什么要有它：关联说明目标关系，不能继承不适用于本片的批次门槛或改写旧工作。
