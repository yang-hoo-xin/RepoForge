## What to build

用户通过正常 CLI / Task Run 明确任务最高费用及绑定费率。系统在实际付费调用前预留最大可能成本，允许范围内的运行并在不足时保存进度、明确停止。恢复、重试和未知在途用量保留累计消耗，不自动增加额度或换模型。
为什么要有它：用户需要可执行的费用边界，而不只是结束后的用量报告。

## Acceptance criteria

- [ ] 配置校验拒绝缺失或非法金额、费率及不支持的模型计费绑定，旧未启用合同保持原解释。
- [ ] 对完整请求和最大输出保守计量；剩余金额不足时 HTTP 不发送，输出预算原因及已有结果。
- [ ] 实际可信用量结算，未知用量保留预留，重复结算不重复收费或释放。
- [ ] 任务恢复沿用绑定费率和累计账本，修改预算不能伪装同一配置的普通恢复。
- [ ] 正常入口受控验证覆盖额度内调用、下一次拒绝、中断恢复、重复回执、未知消耗和价格/模型漂移。
- [ ] 输出区分预算估值、可信用量及实际账单未知，不声称控制了其他客户端或整个账户费用。

为什么要有它：验证应覆盖可观察的停止与恢复行为，避免数学函数通过而实际请求绕开预算。
