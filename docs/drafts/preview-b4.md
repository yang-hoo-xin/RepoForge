## What to build

在干净 Windows x64 环境取得固定版本、安装 CLI、配置已有 C# 项目与模型，完成小范围任务及预算停止/恢复、验证、审阅、应用和撤销。缺依赖或配置错误在付费请求前明确提示。
为什么要有它：安装后的真实入口是试用者接触产品的方式，不能依赖维护者临时目录和开发环境。

## Acceptance criteria

- [ ] 支持范围、依赖版本、模型配置、费用边界和外发范围在安装说明中一致。
- [ ] 源码、安装产物、文档和选定 CI 绑定同一候选提交，安装后入口不依赖 editable 或源码目录。
- [ ] 正常用户流程覆盖已有文件和新建开发测试；受控模型验证与真实模型结果分别标注。
- [ ] 提供结果定位、错误诊断、停止、清理和回退说明，密钥不进入日志或发行物。
- [ ] 工程完成单独登记；不将尚未发生的外部试点写成完成。

为什么要有它：工程就绪与真实采用分开记录，既能交付版本，也保留真实验证缺口。
