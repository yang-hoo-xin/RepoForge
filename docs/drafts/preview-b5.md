## What to build

至少两位非项目开发者各带一个自己的 C# 仓库小范围需求试用，保留采用或拒绝原因，至少一项修改实际采用。安装支持、业务提示与手工代改分别记录。
为什么要有它：可安装和真实有用需要分别验证，模拟用户或开发助手自评不能代替外部采用。

## Acceptance criteria

- [ ] 使用者、需求、版本与运行相互对应，按其许可保留必要记录。
- [ ] 记录独立操作步骤、帮助次数/内容、结果、耗时、费用及未知项，不推算未计量人工时间。
- [ ] 两位使用者各完成一次真实试用，至少一项实际采用；有辅助的结果不称独立完成。
- [ ] 失败和拒绝保留，对直接阻断排序，不通过无限换题或重试凑成功。
- [ ] 用户招募或试点未就绪时准确保留未完成状态，不自动联系他人或生成假反馈。

为什么要有它：试点的价值在真实问题和反馈，人数目标不是统计代表性或营销数据。
