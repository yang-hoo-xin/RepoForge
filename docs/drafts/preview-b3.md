## What to build

用户查看独立副本产生的具体差异、检查结果和费用，确认后将该版本应用到原仓库，并能够撤销本次应用而保留无关工作。复用已有隔离交付，不重做候选生成。
为什么要有它：内部产物通过还需要转成用户能安全接收和退出的操作。

## Acceptance criteria

- [ ] 展示准确的新建/修改差异、测试状态和费用；无批准不修改原仓库。
- [ ] 应用绑定精确差异与当前前像；原仓库变化、已有同名新文件及路径越界被拒绝。
- [ ] 撤销检查应用后状态，恢复本次修改及撤去本次新建文件，不覆盖后续或无关编辑。
- [ ] 重复操作及中断恢复不重复副作用，部分失败给出真实已生效范围和恢复方式。
- [ ] 正常 CLI 受控场景验证审阅、拒绝、批准、应用、冲突与撤销。

为什么要有它：用户需要可控的源码交接，而不是一个不检查当前仓库的补丁覆盖命令。
